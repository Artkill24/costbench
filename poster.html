The gain from batching does not depend on the model

Two models, one twice the size of the other. Normalise each curve by its own concurrency-1 value and they coincide within 1%.

Finding 1
Relative efficiency gain is model-independent

8.70× on the 7B, 8.80× on the 14B — a property of the architecture, not of one model. Four independent sessions, two load patterns, achieved concurrency verified per run.

Finding 2
Absolute efficiency scales inversely with model size

The 14B/7B tokens-per-joule ratio is 0.53 / 0.52 / 0.54 at concurrency 1 / 4 / 16. Double the weights, half the efficiency: the signature of a memory-bandwidth-bound decode.

What it buys
A bill for on-prem inference

A gateway meters every request against the measured curve; an agent reports what each task cost. One recorded task: 194 tokens · 404 J · €0.000028 · 0 bytes egress — the zero verified against a local audit ledger, not asserted.

Four measurement bugs found and fixed — each produced plausible-looking data
Sensor lag ~18 s power1_average is a long-window mean; 2–5 s runs reported 14 W under full load. Fixed with 90 s runs, first 25 s discarded.
Shared 8-GPU host sysfs exposes every card; the first readable path was somebody else's. GPU now resolved by PCI bus, recorded in every result.
Wave-barrier load waiting for all N leaves an idle tail that grows with N, deflating power at high batch. Replaced by closed-loop load.
Stale server on the port a "14B" run re-measured the 7B. The served model is now verified, and the invalid run is kept in rejected/.
